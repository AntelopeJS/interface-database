A change feed sends a notification when a document is inserted, updated, or deleted. Both `Stream<T>` and `SingleSelection<T>` expose a `changes()` method that returns change events.

## The `Changes` interface

```typescript
interface Changes<T> {
  changeType: "added" | "removed" | "modified";
  oldValue?: T;
  newValue?: T;
}
```

| Property     | Description                                                          |
| ------------ | -------------------------------------------------------------------- |
| `changeType` | The type of change: `"added"`, `"removed"`, or `"modified"`.         |
| `oldValue`   | The document value before the change. `undefined` for new documents. |
| `newValue`   | The document value after the change. `undefined` for deletions.      |

## Create a change feed

Calling `changes()` on a stream or a single selection builds a feed query. Async iteration over the feed receives the events as they arrive:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = Schema.get("myapp");
if (!schema) throw new Error("Define the myapp schema first");
const users = schema.instance().table("users");

// Monitor all changes to a table
const allChanges = users.changes();

// Monitor changes to a specific document
const userChanges = users.get("user-123").changes();
```

## Process change events

Each change event has a `changeType` field that tells what kind of change happened:

```typescript fragment
for await (const change of users.changes()) {
  if (change.changeType === "added") {
    console.log("New document:", change.newValue);
  } else if (change.changeType === "modified") {
    console.log("Updated from:", change.oldValue);
    console.log("Updated to:", change.newValue);
  } else {
    console.log("Deleted document:", change.oldValue);
  }
}
```

## Use with async iteration

`changes()` returns `Query<Changes<T>[]>`, but the cursor and the async iterator of `Query` yield each array element. Each iteration gives one `Changes<T>` event, not a batch. A direct `await` calls `run()` and asks the provider for a completed result. An open-ended feed may never complete, so use iteration to watch a feed continuously.

```ts docs-check
import { Schema } from "@antelopejs/interface-database";
import type { Changes } from "@antelopejs/interface-database/common";

interface User {
  _id: string;
  name: string;
}

export async function watchUsers(onChange: (change: Changes<User>) => boolean) {
  const schema = Schema.get<{ users: User }>("myapp");
  if (!schema) throw new Error("Register the myapp schema first");
  const feed = schema.instance().table("users").changes();

  for await (const change of feed) {
    console.log(`${change.changeType}:`, change.newValue ?? change.oldValue);
    if (!onChange(change)) break;
  }
}
```

Breaking out of the loop closes its cursor. If you call `cursor()` yourself, call `return()` on the cursor when you are done.

## Use cases

Change feeds fit these uses:

- Real-time UI updates, which push changes to connected clients as they happen.
- Event-driven architectures, which react to data changes with downstream processing.
- Change observation, which sees writes while a feed is active. Durable auditing needs delivery and recovery guarantees from the provider. This interface alone does not promise a complete audit log.
- Cache invalidation, which clears or updates caches when the underlying data changes.
