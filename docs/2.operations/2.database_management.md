---
title: Schema management
description: Define an AQL schema, then create, access, list, and destroy its instances, one per tenant if you need isolation.

---

AQL organizes data through schemas and instances. A `Schema` defines the structure of your database: tables, fields, and indexes. Each schema can have many instances, and the database module that implements the interface decides how instances map to physical storage.

## Define a schema

Create a schema from an ID and a definition of its tables, each with its fields and indexes:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = new Schema("myapp", {
  users: {
    fields: { name: "string", email: "string", role: "string" },
    indexes: {
      email: {},
      role: {},
    },
  },
  posts: {
    fields: { title: "string", content: "string", authorId: "string" },
    indexes: {
      authorId: {},
    },
  },
});
```

The ID names the stored data. Changing it leaves the data stored under the previous ID out of reach.

### `SchemaDefinition`

A schema definition is a record that maps each table name to its `TableDefinition`:

```typescript
import type { FieldType } from "@antelopejs/interface-database/schema";

interface TableDefinition {
  fields: Record<string, FieldType>;
  indexes: Record<string, IndexDefinition>;
}

interface IndexDefinition {
  fields?: string[]; // For compound indexes
  multi?: boolean; // Multi-valued index
  crossInstance?: boolean; // Also serve cross-instance queries
  unique?: boolean; // No two rows of one instance share the key
}
```

## Create an instance

After you define a schema, create an instance to start working with data. The optional `id` parameter tells instances of the same schema apart, and `createInstance()` resolves to the ID of the created instance.

```typescript fragment
// Create the default instance
await schema.createInstance().run();

// Create a named instance
await schema.createInstance("tenant-abc").run();
```

## Access an instance

Get a `SchemaInstance` to access its tables:

```typescript fragment
// Default instance
const db = schema.instance();

// Named instance
const tenantDb = schema.instance("tenant-abc");
```

To operate across every instance of the schema, pass the `CROSS_INSTANCE` sentinel. It removes the instance boundary for the queries that support it, updates and deletes included. Keep it out of request paths that a tenant controls. Selecting an instance does not authorize the caller.

```typescript fragment
import { CROSS_INSTANCE } from "@antelopejs/interface-database";

const everything = schema.instance(CROSS_INSTANCE).table("users");
```

## Destroy an instance

Remove an instance and its data:

```typescript fragment
await schema.destroyInstance("tenant-abc").run();
```

## List instances

List the IDs of the named instances of a schema:

```typescript fragment
const ids = await schema.listInstances().run();
// ["tenant-abc", "tenant-xyz"]
```

The list leaves out the default (unnamed) instance.

## Retrieve a schema

Look up a schema defined elsewhere by its ID with the static `Schema.get()` method. It returns `undefined` when no schema has that ID:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = Schema.get("myapp");

if (schema) {
  const users = schema.instance().table("users");
}
```

## Work with tables

Put the table-to-document mapping on `Schema`, then access tables by name. The type parameter of `table()` is a key of that mapping, not a document type:

```typescript
import { Schema } from "@antelopejs/interface-database";

interface User {
  _id: string;
  name: string;
  email: string;
  role: string;
}

interface Post {
  _id: string;
  title: string;
  content: string;
  authorId: string;
}

const typedSchema = new Schema<{ users: User; posts: Post }>("myapp", {
  users: {
    fields: { name: "string", email: "string", role: "string" },
    indexes: {},
  },
  posts: {
    fields: { title: "string", content: "string", authorId: "string" },
    indexes: {},
  },
});

const db = typedSchema.instance();
const users = db.table("users"); // Table<User>
const posts = db.table("posts"); // Table<Post>
```

The type argument describes the schema. It does not validate stored data. `Schema.get()` keeps no type arguments: the schema it returns maps each table to `any` documents. Export the schema object you define and import it where you query typed tables.

## Multi-tenant pattern

A schema with many instances suits a multi-tenant application. Each tenant gets an isolated instance of the same schema:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = new Schema("saas", {
  projects: {
    fields: { name: "string" },
    indexes: {},
  },
});

// Create one instance per tenant
await schema.createInstance("tenant-1").run();
await schema.createInstance("tenant-2").run();

// Access tenant-specific data
const tenant1Projects = schema.instance("tenant-1").table("projects");
const tenant2Projects = schema.instance("tenant-2").table("projects");
```
