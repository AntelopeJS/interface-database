CRUD stands for create, read, update, and delete. The examples on this page assume a schema is already defined and use its default instance:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = Schema.get("myapp");
if (!schema) throw new Error('Schema "myapp" is not defined');

const users = schema.instance().table("users");
```

## Create documents

### Insert a single document

`insert()` resolves to the IDs of the inserted documents.

```typescript fragment
const ids = await users.insert({
  name: "Alice Johnson",
  email: "alice@example.com",
  status: "active",
  createdAt: new Date(),
});

console.log("Inserted ID:", ids[0]);
```

### Insert multiple documents

```typescript fragment
const ids = await users.insert([
  { name: "Bob", email: "bob@example.com", status: "active" },
  { name: "Carol", email: "carol@example.com", status: "active" },
]);

console.log("Inserted IDs:", ids);
```

### Duplicate keys

Without a `conflict` option, an insert throws a `DuplicateKeyError` when the instance already holds the row's `_id` or its key in a [unique index](./5.indexes.md#unique-indexes). An update or a replacement that would duplicate a unique key throws it too. Nothing of the refused write is stored for the row that hit the duplicate. When a batch insert hits a duplicate, the database decides whether its other rows are stored.

```typescript fragment
import { IsDuplicateKeyError } from "@antelopejs/interface-database";

try {
  await users.insert({ _id: "user-123", name: "Alice" });
} catch (error) {
  if (!IsDuplicateKeyError(error)) throw error;
  // error.index === "_id", error.fields deep-equals ["_id"]
}
```

### Upsert (insert or update)

To handle documents that already exist, set the `conflict` option to `"update"` or `"replace"`:

```typescript fragment
// Update existing fields, keep unmentioned fields
await users.insert(
  { _id: "user-123", name: "Updated Name", lastSeen: new Date() },
  { conflict: "update" },
);

// Replace the entire document
await users.insert(
  { _id: "user-123", name: "Replaced", email: "new@example.com" },
  { conflict: "replace" },
);
```

## Read documents

### Get by primary key

```typescript fragment
const user = await users.get("user-123");

if (user) {
  console.log("Found:", user.name);
} else {
  console.log("User not found");
}
```

### Get by secondary index

```typescript fragment
const admins = await users.getAll("admin", "role");
console.log(`Found ${admins.length} admins`);
```

### Get by range

The upper bound of `between()` is excluded.

```typescript fragment
const recent = await users.between(
  "createdAt",
  new Date("2024-01-01"),
  new Date(),
);
```

### Filter documents

```typescript fragment
// Filter with a predicate function
const active = await users.filter((user) =>
  user.key("status").eq("active").and(user.key("age").ge(18)),
);
```

### Select specific fields

```typescript fragment
// Keep only listed fields
const profiles = await users.pluck("_id", "name", "avatar");

// Remove sensitive fields
const safe = await users.without("password", "ssn");
```

### Order and paginate

`slice()` takes an offset and a count.

```typescript fragment
const page1 = await users.orderBy("createdAt", "desc").slice(0, 10);
const page2 = await users.orderBy("createdAt", "desc").slice(10, 10);
```

### Stream results

For a large result set, iterate with `for await` to process one document at a time:

```typescript fragment
for await (const user of users) {
  console.log("Processing:", user.name);
}
```

## Update documents

`update()` takes either a partial document or a function that builds one. It returns a `Query<number>` that resolves to the number of modified documents.

### Update a single document

Pass a partial document. `update()` changes the fields it names and keeps every other field.

```typescript fragment
const count = await users.get("user-123").update({
  status: "active",
  lastLogin: new Date(),
});

if (count === 1) {
  console.log("User updated");
}
```

Give the partial document a real type. A value typed `any` matches the function overload of `update()`, and that call is typed `never`, so it has no `.run()`.

### Update with computed values

Pass a function to compute new values from the current ones:

```typescript fragment
await users.get("user-123").update((user) => ({
  loginCount: user.key("loginCount").add(1),
  lastLogin: new Date(),
}));
```

The call is typed `Query<number>` when the object the function returns fits the document type, and `never` otherwise.

### Update multiple documents

```typescript fragment
const count = await users
  .getAll("inactive", "status")
  .update({ status: "active" });

console.log(`Activated ${count} users`);
```

## Replace documents

`replace()` swaps in the whole document. It removes the fields that the replacement leaves out, and it resolves to the number of modified documents.

```typescript fragment
const count = await users.get("user-123").replace({
  _id: "user-123",
  name: "Alice Updated",
  email: "alice.new@example.com",
  status: "active",
  updatedAt: new Date(),
});
```

## Delete documents

`delete()` resolves to the number of deleted documents.

### Delete a single document

```typescript fragment
const count = await users.get("user-123").delete();

if (count === 1) {
  console.log("User deleted");
}
```

### Delete multiple documents

```typescript fragment
const count = await users
  .filter((user) => user.key("status").eq("inactive"))
  .delete();

console.log(`Deleted ${count} inactive users`);
```

## Batch operations

For a large insert, split the documents into batches to bound memory use and the size of each write:

```typescript fragment
const documents = Array.from({ length: 10000 }, (_, i) => ({
  index: i,
  value: `Item ${i}`,
  createdAt: new Date(),
}));

const batchSize = 1000;
for (let i = 0; i < documents.length; i += batchSize) {
  const batch = documents.slice(i, i + batchSize);
  await schema.instance().table("items").insert(batch);
  console.log(`Inserted batch ${Math.floor(i / batchSize) + 1}`);
}
```
