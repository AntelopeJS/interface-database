An index lets the database find documents by the indexed fields without scanning the whole table. In AQL, you declare indexes in the schema definition.

## Define indexes in a schema

Declare indexes in the `indexes` property of each table definition:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = new Schema("myapp", {
  users: {
    fields: { name: "string", email: "string", role: "string", age: "number" },
    indexes: {
      email: {}, // Simple index on the "email" field
      role: {}, // Simple index on the "role" field
      name_age: { fields: ["name", "age"] }, // Compound index
    },
  },
});
```

### `IndexDefinition`

```typescript
interface IndexDefinition {
  fields?: string[]; // Fields for compound indexes (omit for single-field)
  multi?: boolean; // Whether this is a multi-valued index
  crossInstance?: boolean; // Also serve CROSS_INSTANCE queries efficiently
  unique?: boolean; // Refuse a second row with the same key in an instance
}
```

When you omit `fields`, the index name is the field name. For a compound index, list its fields in the `fields` array.

A dotted entry in `fields`, or a dotted index name without `fields`, is a nested path. `"title.fr"` indexes `fr` inside `title`, never a top-level key named `title.fr`.

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = new Schema("catalog", {
  articles: {
    fields: {
      title: { fr: "string", en: "string" },
    },
    indexes: {
      title_fr: { fields: ["title.fr"] },
      "title.en": {},
    },
  },
});
```

## Use indexes for queries

### `getAll()` with an index

Get the documents whose index value matches one or more keys:

```typescript fragment
const db = schema.instance();
const users = db.table("users");

// Query by the "role" index
const admins = await users.getAll("admin", "role");

// Query multiple values
const targets = await users.getAll(["admin", "moderator"], "role");
```

### `between()` with an index

Get the documents whose index value falls in a range. The upper bound is excluded:

```typescript fragment
const results = await users.between("age", 18, 65);
```

### `orderBy()` with an index

Sort results on an indexed field for better performance:

```typescript fragment
const sorted = await users.orderBy("email", "asc");
const newest = await users.orderBy("createdAt", "desc");
```

`orderBy()` takes an index name, or else a field. A dotted field is a nested path, so `orderBy("meta.rank")` sorts on `rank` inside `meta` when no index has that name.

## Compound indexes

A compound index spans several fields. Define it with the `fields` array:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = new Schema("blog", {
  posts: {
    fields: {
      category: "string",
      publishedAt: "date",
      title: "string",
    },
    indexes: {
      category_date: { fields: ["category", "publishedAt"] },
    },
  },
});
```

A compound index supports prefix lookups. You can query by the first field alone or by both fields together.

## Multi indexes

Set `multi: true` for a field that holds an array. The database creates an index entry for each element of the array, so a lookup by any single element finds the document:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = new Schema("content", {
  articles: {
    fields: { tags: ["string"] },
    indexes: {
      tags: { multi: true },
    },
  },
});
```

## Cross-instance indexes

An index is optimized for queries scoped to one instance (`schema.instance(id)`). A query run with `schema.instance(CROSS_INSTANCE)` can still use it, but may be slow. Set `crossInstance: true` on the indexes that cross-instance queries rely on, and the driver also maintains an index usable by those queries:

```typescript
import { CROSS_INSTANCE, Schema } from "@antelopejs/interface-database";

const schema = new Schema("billing", {
  invoices: {
    fields: { status: "string" },
    indexes: {
      status: { crossInstance: true },
    },
  },
});

// Efficient on every instance at once
await schema
  .instance(CROSS_INSTANCE)
  .table("invoices")
  .getAll("unpaid", "status");
```

The flag defaults to `false`. It never changes query results, only performance. Each flagged index costs extra storage and write overhead, so set it only where cross-instance queries use the index.

## Unique indexes

Set `unique: true` to refuse a second row with the same key in one instance. The write that would store it throws a `DuplicateKeyError`, which names the index and its fields. The primary key `_id` is always unique and throws the same error, with `index` set to `"_id"`:

```typescript
import { IsDuplicateKeyError, Schema } from "@antelopejs/interface-database";

interface User {
  _id: string;
  email: string;
}

const schema = new Schema<{ users: User }>("myapp", {
  users: {
    fields: { email: "string" },
    indexes: {
      email: { unique: true },
    },
  },
});

try {
  await schema
    .instance("acme")
    .table("users")
    .insert({ email: "ada@example.com" });
} catch (error) {
  if (!IsDuplicateKeyError(error)) throw error;
  console.log(`Taken: ${error.fields.join(", ")} on index ${error.index}`);
}
```

The key is unique within each instance, so two instances may hold the same email. `crossInstance` does not change that. Give every row a value for the fields of a unique index, because databases differ on whether rows that lack them conflict.

Recognize the error with `IsDuplicateKeyError` rather than `instanceof`. The database module may be bound to another copy of the interface.

## Index design guidelines

- Index the fields that your `getAll()` and `between()` calls use.
- Add a compound index when you often filter or sort by the same fields together.
- Avoid over-indexing. Each index adds storage and slows down writes.
- Filter early in the query chain to reduce the number of documents processed.
