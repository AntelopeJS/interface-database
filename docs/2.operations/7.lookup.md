---
title: Lookup
description: Replace a foreign key field of AQL documents with the document, or the array of documents, it references in another table.

---

`lookup()` runs a foreign key join. It replaces a field of your documents with the documents that field references in another table. Both `Stream<T>` and `Datum<T>` have it.

## Parameters

| Parameter  | Type               | Description                                               |
| ---------- | ------------------ | --------------------------------------------------------- |
| `other`    | `Stream<U>`        | The table containing the referenced documents             |
| `localKey` | `keyof T & string` | The field in the current document holding the foreign key |
| `otherKey` | `FieldPath<U>`     | The field in the other table to match against             |

`Stream.lookup()` names its first parameter `right`. `Datum.lookup()` names it `other`.

## Behavior

`lookup()` replaces the local key field with the referenced data:

- If the local key holds a **single value**, the field becomes a **single document** from the other table.
- If the local key holds an **array of values**, the field becomes an **array of documents** from the other table.
- The result type follows the same rule: `Omit<T, TK> & Record<TK, T[TK] extends any[] ? U[] : U>`, where `TK` is the local key.

## One-to-one relationship

Replace a single foreign key with the referenced document:

```typescript
import { Schema } from "@antelopejs/interface-database";

interface Post {
  _id: string;
  title: string;
  authorId: string;
}

interface User {
  _id: string;
  name: string;
  email: string;
}

const schema = Schema.get<{ posts: Post; users: User }>("blog");
if (!schema) throw new Error('Schema "blog" is not defined');

const db = schema.instance();

const postsWithAuthors = await db
  .table("posts")
  .lookup(db.table("users"), "authorId", "_id");

// Result type: { _id: string, title: string, authorId: User }
for (const post of postsWithAuthors) {
  console.log(`${post.title} by ${post.authorId.name}`);
}
```

## One-to-many relationship

Replace an array of foreign keys with an array of documents:

```typescript
import { Schema } from "@antelopejs/interface-database";

interface Order {
  _id: string;
  customerId: string;
  productIds: string[];
  total: number;
}

interface Product {
  _id: string;
  name: string;
  price: number;
}

const shopSchema = Schema.get<{ orders: Order; products: Product }>("shop");
if (!shopSchema) throw new Error('Schema "shop" is not defined');

const shop = shopSchema.instance();
const ordersWithProducts = await shop
  .table("orders")
  .lookup(shop.table("products"), "productIds", "_id");

// Result type: { ..., productIds: Product[] }
for (const order of ordersWithProducts) {
  for (const product of order.productIds) {
    console.log(`  - ${product.name}: $${product.price}`);
  }
}
```

## Match a nested key

A dotted `otherKey` is a nested path in the other document. `"meta.sku"` matches the `sku` inside `meta`, never a top-level key named `meta.sku`. `localKey` stays a top-level field.

```typescript
import { Schema } from "@antelopejs/interface-database";

interface OrderLine {
  _id: string;
  productRef: string;
}

interface Product {
  _id: string;
  meta: { sku: string };
}

const catalogSchema = Schema.get<{ lines: OrderLine; products: Product }>(
  "catalog",
);
if (!catalogSchema) throw new Error('Schema "catalog" is not defined');

const catalog = catalogSchema.instance();

const linesWithProducts = await catalog
  .table("lines")
  .lookup(catalog.table("products"), "productRef", "meta.sku");

// Result type: { _id: string, productRef: Product }
for (const line of linesWithProducts) {
  console.log(line.productRef.meta.sku);
}
```

## Combine with other operations

`lookup()` chains with filters, sorting, and the other stream operations:

```typescript fragment
// The shop schema also declares customers and orders.createdAt.
const shopSchema = Schema.get("shop");
if (!shopSchema) throw new Error('Schema "shop" is not defined');
const db = shopSchema.instance();

// Filter before lookup
const recentWithCustomers = await db
  .table("orders")
  .filter((order) => order.key("createdAt").gt(new Date("2024-01-01")))
  .lookup(db.table("customers"), "customerId", "_id");

// Lookup on a single document
const blogSchema = Schema.get<{ posts: Post; users: User }>("blog");
if (!blogSchema) throw new Error('Schema "blog" is not defined');
const blog = blogSchema.instance();
const post = await blog
  .table("posts")
  .get("post-1")
  .lookup(blog.table("users"), "authorId", "_id");
```

## Lookup vs join

### Use `lookup` when:

- You have a plain foreign key relationship.
- You want the referenced data to replace the foreign key field.
- You work with one-to-one or one-to-many relationships.

### Use `join` or `joinInner` when:

- You need a join predicate other than equality of two fields.
- You want to keep the original and the joined data as separate fields.
- You need to transform the result into a custom structure.

### Comparison

```typescript fragment
// Lookup: replaces the field
const withLookup = await db
  .table("orders")
  .lookup(db.table("customers"), "customerId", "_id");
// order.customerId is now the full customer object

// Join: custom output structure
const withJoin = await db.table("orders").joinInner(
  db.table("customers"),
  (order, customer) => order.key("customerId").eq(customer.key("_id")),
  (order, customer) => ({
    orderId: order.key("_id"),
    orderTotal: order.key("total"),
    customerName: customer.key("name"),
  }),
);
// Result is a custom object with selected fields from both tables
```
