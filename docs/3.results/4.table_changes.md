In AQL, a schema defines its tables. Each table definition lists the fields and indexes of that table.

## `TableDefinition`

```typescript
import type {
  FieldType,
  IndexDefinition,
} from "@antelopejs/interface-database/schema";

interface TableDefinition {
  fields: Record<string, FieldType>;
  indexes: Record<string, IndexDefinition>;
}
```

### `FieldType`

A field type describes the structure of one field:

```typescript
type StringFieldType =
  | string // Primitive type name, such as "string" or "number"
  | Array<StringFieldType> // Array of a given type
  | { [subfield: string]: StringFieldType }; // Nested object

interface IoTsValidation {
  readonly _tag: "Left" | "Right";
}

type IoTsCodec<A = unknown, O = unknown, I = unknown> = {
  readonly _A: A;
  readonly _O: O;
  readonly _I: I;
  readonly name: string;
  is(u: A | I): boolean;
  encode(a: A): O;
  decode(i: I): IoTsValidation;
};

type FieldType = StringFieldType | IoTsCodec; // io-ts codec at the field root
```

`@antelopejs/interface-database/schema` exports `StringFieldType` and `FieldType`. `IoTsCodec` and `IoTsValidation` are not exported. They are shown here as the shape a codec must have.

A field uses either the string-token vocabulary (primitives, arrays, nested records) or a single [io-ts](https://github.com/gcanti/io-ts) codec at the root of the field. Any io-ts `Type` fits. The type requires its `_A`, `_O`, `_I`, `name`, `is`, `encode`, and `decode` members, and `decode` must return a value tagged `Left` or `Right`, as an io-ts `Either` is. A string-tree record cannot hold a codec. To nest inside a codec, use io-ts combinators such as `t.type` and `t.array`.

```typescript
import * as t from "io-ts";

const Order = {
  fields: {
    id: "string",
    status: t.union([t.literal("open"), t.literal("closed")]),
    meta: t.type({ source: t.string, retries: t.number }),
  },
  indexes: {},
};
```

## Define tables in a schema

The `SchemaDefinition` passed to the `Schema` constructor declares the tables:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = new Schema("myapp", {
  users: {
    fields: {
      name: "string",
      email: "string",
      age: "number",
      address: {
        street: "string",
        city: "string",
        zip: "string",
      },
      tags: ["string"],
    },
    indexes: {
      email: {},
      age: {},
    },
  },
  posts: {
    fields: {
      title: "string",
      content: "string",
      authorId: "string",
      publishedAt: "date",
    },
    indexes: {
      authorId: {},
      publishedAt: {},
    },
  },
});
```

## Access tables

After you create a schema instance, access its tables by name:

```typescript fragment
await schema.createInstance();

const users = schema.instance().table("users");
const posts = schema.instance().table("posts");
```

For typed access, give the table mapping when you declare or retrieve the schema. `table()` infers the document type from the table name:

```typescript
import { Schema } from "@antelopejs/interface-database";

interface User {
  _id: string;
  name: string;
  email: string;
  age: number;
}

const typedSchema = Schema.get<{ users: User }>("myapp");
if (!typedSchema) throw new Error('Schema "myapp" is not defined');

const users = typedSchema.instance().table("users"); // Table<User>
```

For more on table operations, see [Table operations](../2.operations/3.table_operations.md).
