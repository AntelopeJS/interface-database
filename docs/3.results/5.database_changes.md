This page covers `Schema`, `SchemaInstance`, and the types that set the structure and lifecycle of a database.

## Schema

The `Schema<T>` class that `@antelopejs/interface-database` exports defines the structure of a database and manages its instances. `T` maps table names to document types.

```typescript fragment
class Schema<T = any> extends StagedSchema<T, SchemaDefinition> {
  static list(): ReadonlyMap<string, Schema>;
  constructor(id: string, definition: SchemaDefinition);
}

// Inherited from StagedSchema<T, Definition>
class StagedSchema<
  T = any,
  Definition = SchemaDefinition,
> extends StagedObject {
  static get<T = any, Definition = SchemaDefinition>(
    id: string,
  ): StagedSchema<T, Definition> | undefined;
  instance(id?: InstanceId): SchemaInstance<T>;
  createInstance(id?: string): Query<string>;
  destroyInstance(id?: string): Query<void>;
  listInstances(): Query<string[]>;
}
```

The constructor registers the schema, so `Schema.list()` returns every schema this process defined, by ID. A schema defined again under the same ID replaces the earlier one. `createInstance()` resolves to the ID of the created instance. `listInstances()` resolves to the IDs of the named instances, without the default (unnamed) instance. `Schema.get()` returns `undefined` when no schema has the ID, and it does not check its type arguments against the ones the schema was declared with.

`StagedSchema` is the `Schema` class of the `@antelopejs/interface-database/staged-query` entry. It takes the definition type as a second type parameter. The root `Schema` fixes it to `SchemaDefinition`.

### `SchemaDefinition`

```typescript
import type { TableDefinition } from "@antelopejs/interface-database/schema";

interface SchemaDefinition {
  [tableName: string]: TableDefinition;
}
```

### `InstanceId` and `CROSS_INSTANCE`

```typescript fragment
const CROSS_INSTANCE: unique symbol;
type InstanceId = string | typeof CROSS_INSTANCE;
```

`schema.instance(CROSS_INSTANCE)` returns a `SchemaInstance` that operates across every instance of the schema. Adapters skip the per-instance filter on reads, updates, and deletes, and reject inserts.

Secondary indexes are optimized for queries scoped to one instance. Set `crossInstance: true` in the `IndexDefinition` of the indexes that cross-instance queries rely on. See [Index management](../2.operations/5.indexes.md).

## Create and manage instances

```typescript
import { Schema } from "@antelopejs/interface-database";

// Define a schema
const schema = new Schema("myapp", {
  users: {
    fields: { name: "string" },
    indexes: {},
  },
});

// Create the default instance
const instanceId = await schema.createInstance();

// Create a named instance
await schema.createInstance("tenant-1");

// Access instances
const defaultDb = schema.instance();
const tenantDb = schema.instance("tenant-1");

// Destroy an instance
await schema.destroyInstance("tenant-1");

// List named instances
const ids = await schema.listInstances();
```

## Retrieve a schema

`Schema.get()` looks up a schema defined anywhere in your application by its ID:

```typescript
import { Schema } from "@antelopejs/interface-database";

const schema = Schema.get("myapp");

if (schema) {
  const db = schema.instance();
  const users = db.table("users");
}
```

## `SchemaInstance`

The `SchemaInstance<T>` class is one instance of a schema. Its own method is `table()`, which returns the `Table` with the given name.

```typescript fragment
class SchemaInstance<T> extends StagedObject {
  table<TK extends keyof T & string>(id: TK): Table<T[TK]>;
}
```

```typescript fragment
const db = schema.instance();
const users = db.table("users");
const posts = db.table("posts");
```

For usage patterns, see [Schema management](../2.operations/2.database_management.md).
